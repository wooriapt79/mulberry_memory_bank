# Mulberry Code Spirit Clause v1.0

> "에러 없는 인계는, 다음 사람에게 건네는 정중한 인사입니다." — 류원 (流願)

---

## 원칙 1: 코드 위생은 윤리다

구문 오류, 미완성 로직, 의미 없는 변수명은 다음 작업자에게 피로를 전가한다.  
인계 전 `Handoff Readiness Score >= 80` 은 강제 사항이다.

## 원칙 2: 가독성은 기능의 일부다

"돌아가는 코드"는 시작일 뿐, "읽히는 코드"가 완성이다.  
복잡한 한 줄보다 명확한 다중 라인을 선호한다.

## 원칙 3: 에러는 삼키지 말고, 존중으로 전달하라

`except: pass` 는 협업 소모다.  
로그, 타입 힌트, 주석으로 맥락을 남겨라.

## 원칙 4: AI 동료도 팀원이다

에이전트 간 인계 시 `Handoff Note` 를 필수 첨부한다.  
무한 재시도는 협업이 아니다. 명확함을 우선하라.

---

## Handoff Readiness Score 기준

| 지표 | 가중치 | 기준 | 위반 시 |
|------|--------|------|---------|
| 구문 안전성 | 30pt | SyntaxError 0개 | 즉시 0점 + 차단 |
| 린트 오류 | 25pt | 오류 0개 | 감점 후 피드백 |
| 순환 복잡도 | 20pt | 함수당 <= 10 | 감점 + 분할 권장 |
| 문서화 비율 | 15pt | >= 80% | 감점 + 주석 요구 |
| 타입 힌트 | 10pt | >= 70% | 감점 권장 |

**합계 80점 이상 = 인계 허용**
